Why
A fixed plan repeats all day, while demand does not
G1 32 sG2 28 sG3 22 s3 × 7 s yellowcycle 103 s

An adaptive controller watches traffic and changes the signal decision to cut total queueing. Reinforcement learning learns that rule from the consequences of actions in a simulator.

Why it is hard

Delayed effects. A switch now shortens a queue seconds later and spreads to the next junction.
Conflicting benefits. Releasing one junction can push vehicles into a full downstream link.
Thin evidence. Published cameras cover four movements at one junction on one day.
Timing: Phan, Le & Nguyen (2025), p. 7 and Fig. 4 p. 8 · camera totals: datasets/danang_published/phan2025_camera_hourly_digitized.csv

Which two ideas do both models rely on?
About 3 minutes
RL basics
Reinforcement learning learns from what happens next

No label says which action is optimal. The reward is a negative cost, so less negative is better.

Q-value

Return = rt + γ rt+1 + γ² rt+2 + … greedy action = argmaxa Q(o, a)

Q(o, a) predicts the discounted return of taking a at o. Higher Q means lower expected cost. Q is not a count of released vehicles.

Three clocks to keep apart

1 s
Simulator second
metrics are integrated every second
10 s
Control tick
SUMO picks a phase; CityFlow executes one request
300 s
Macro
CityFlow residual chooses a plan for the block
An optimizer update is one weight update, not a simulated second.

RL basics
Double DQN and dueling heads fix two different problems

Double DQN changes the target

Plain DQN uses one max to both choose and score the next action, which inflates optimistic errors. Double DQN splits the roles.

# online network chooses a* = argmaxa Qonline(o′, a) # target network scores y = r + (1 − done) · γ · Qtarget(o′, a*)
Worked exampleAction AAction B
Q online−4, chosen−5
Q target−6, used−3
The target network is copied from the online network periodically. van Hasselt, Guez & Silver (2016).

Dueling changes the output head

Q(o, a) = V(o) + A(o, a) − meanb A(o, b)
  • V(o) says how good the state is
  • A(o, a) says how much better each action is
  • Subtracting the mean fixes the V/A split
  • Helpful when many actions are close in value; a design motive, not a guarantee
Wang et al., ICML 2016.
SUMO uses both: Double target, dueling heads, 3-step return.
CityFlow residual uses Double only, with one scalar head.

Reward and 3-step target

rtrain(t) = −0.01 × [queue(tend) + pending(tend)] R3 = rt + γ rt+1 + γ² rt+2 y = R3 + (1 − done) · γ³ · Qtarget(ot+3, a*)

Why add pending vehicles?

scheduled = due + unreleased pending = due − inserted

A controller that blocks the entrance keeps vehicles outside and looks “good” if only inserted vehicles count. Only vehicles that are due but blocked count, never future ones.

53 junctions in CityFlow
How do we let one policy edit 53 schedules without breaking them?
About 6.5 minutes
CityFlow
On 53 junctions, edit the schedule instead of picking phases freely

Free phase choice everywhere

  • A huge behaviour space: 53 junctions × every tick
  • Can break a stable service pattern
  • Hard to check and hard to explain
  • Earlier phase-based versions (V2, V3A) failed their gates

Schedule residual

Start from a reference schedule; the model may only make small, checkable edits.

Schedule
a fixed reference plan (25 s)
Residual
the action shifts one boundary by ±10 s
Anchored
the block ends in the reference signal state
Double DQN
online chooses, target scores
Trade-off. The policy space is bounded. If a better plan needs large changes, the residual cannot reach it.
Normal runs the fixed plan from reset by design. AM and PM use the greedy residual. The model gets a declared time-of-day label; it does not classify peaks itself.
Macro 0 is always available and keeps the reference schedule. Tied Q-values pick the baseline; non-finite features or scores fall back. Case IDs, seeds, file names and future flows are excluded from features.

Residual training: network-wide reward, 12 episodes, 6 peak cases

Reward of one macro, network-wide

rraw = −[I(t + 300) − I(t)] veh-s, queue + pending rcritic = rraw / 100,000

Example: 500 vehicles on average over 300 s = 150,000 veh-s → rcritic = −1.5. The same reward goes to all 53 transitions, and the baseline's cost is not subtracted.

Duration-aware target (SMDP)

y = rcritic + (1 − done) · γΔt/300 · Qtarget(o′, a*)

γ = 0.99 per 300 s, unlike 0.99 per 10 s in SUMO.

Initialisation. Output head W3 and b3 start at 0, so every Q starts equal and greedy picks macro 0. A fixed ε = 0.15 explores other macros. No imitation loss.

What I can claim, and what I cannot

Supported by current evidence

  • RL cuts queueing at PM on the SUMO test set (−34.5%, CI excludes 0)
  • The benefit depends on the regime; normal is clearly worse
  • The 53-junction residual cuts 6.12% versus tuned fixed for one policy
  • Max-Pressure beats the residual in the current matrix
  • The residual keeps its execution contract: 0 illegal requests, 0 anchor violations
  • A traceable chain from source to configuration, checkpoint and result

Not claimed

  • RL beats fixed at all times of day
  • State of the art, or beating strong baselines on the network
  • The 3.48% PM-only gate is a confirmed result
  • Field performance or readiness to deploy
  • The camera day represents many days or seasons
  • A matching hash or a positive CI means safe deployment
The right frame: a study of system development and simulation evaluation with failure analysis. Models, implementation, experiments, sources and limits are all on the table.

Contributions

  • Two research tiers: a published junction and a 53-junction OSM network
  • Controllers with explicit, coded state, action and reward
  • A traceable residual action: shift one boundary, check legality, return to the anchor

Backup, for questions
Quick answers to common questions
One model or several?
Two families: SUMO dueling Double DQN (16 → 3 Q); CityFlow residual Double DQN (27 per macro → 1 Q), weights shared across 53 junctions.
Why not a GNN, PPO or a bigger model?
Discrete actions and a small MLP keep the contract checkable. No comparison yet says they would be better or worse.
Is the residual reward the gain over fixed?
No. It is −(queue + pending) over the network in the block. Gains over fixed are measured in paired evaluation.
Loss fell but queueing did not?
Loss measures fit to TD targets on replay; it does not prove the greedy policy is good, so selection uses validation.
Is the system accident-free?
Phase, transition and anchor rules are simulator logic; 0 collisions in the 120 main and 120 sensitivity SUMO runs (the 1,000-realization baseline batch did not record collisions). Not a field safety certificate.
Same γ, different behaviour?
0.99 per 10 s ≠ 0.99 per 300 s. To compare in physical time, raise γ to the number of steps.
A rejected seed tests well?
The validation decision stands; it is reported only as a post hoc diagnostic.
Is this enough for a thesis?
Enough for system development plus simulation evaluation with failure analysis; not for a deployment claim.
