# A/B replay: DQN vs baseline on the real network (browser, no container)

This is the **honest DQN demo**. It replays real CityFlow simulation logs
(`results/haichau_rush/demo/replay_*_demo.txt`) recorded on the real 53-node
Hải Châu arterial network, side by side, frame-synchronized. The scoreboard
reports the actual Chapter 4 cumulative-waiting-time numbers computed from
`results/haichau_rush/comparison.json`: DQN **−30.8%** and Max-Pressure
**−40.1%** waiting-time reduction vs Fixed-Time. Nothing on this page is
simulated live or approximated — it is a viewer over pre-recorded, real
episode logs from the same scenario/seed (`haichau_rush`).

Contrast with the toy sandbox (`docs/demo_sandbox.md`, `frontend/sandbox.html`):
that page runs the trained DQN weights live in the browser, but on a single
hand-built intersection micro-model with simplified dynamics. It is useful to
watch the policy make decisions in real time, but the trained agent's
*behavior does not transfer* to that toy model — it is an illustrative concept
toy, not a DQN result. Do not cite sandbox behavior as evidence of anything
quantitative. This A/B replay page is the one with real, citable numbers.

## Run the demo
```
python scripts/serve_replay.py --no-browser
# open http://localhost:8080/frontend/replay_ab.html
```
(No CityFlow/Docker container needed at demo time — the replay logs and
roadnet were already generated by the Chapter 4 evaluation run.)

## What it shows
- Two canvases, left and right, each rendering the same `haichau_rush`
  roadnet with live traffic-light phase coloring (green/red dots on each
  controlled approach) and moving vehicles, reconstructed from the recorded
  CityFlow replay text.
- Each side defaults to a different controller (left: Fixed-Time, right: DQN)
  so the improvement is visible at a glance; either side can be switched
  independently via its dropdown among Fixed-Time, RL (DQN), Max-Pressure,
  and Random.
- A scoreboard below the canvases shows each side's cumulative waiting time
  in vehicle-hours for the full episode and its percentage vs Fixed-Time,
  taken directly from `comparison.json` (the same numbers reported in
  Chapter 4) — not recomputed or estimated client-side.

## Controls
- **Play / Pause** — animate both panels forward in lockstep.
- **Scrub** — drag to any step; both panels stay synchronized to the same
  simulation step.
- **Speed** — adjust playback speed (steps per second).
- **Zoom cụm nút (cluster zoom)** — toggle from the full-network view to a
  zoomed view centered on the 8 intersections nearest the network centroid,
  useful for seeing individual signal-phase behavior.

## Tests
```
node --test tests/replay_ab/*.test.cjs   # parseRoadnet/parseReplay/roadSignal/makeTransform/waitHours/scoreboard
```
These test the pure data/geometry functions (`frontend/replay_ab_core.js`)
that back the canvas rendering and scoreboard math; they are the faithfulness
gate that the on-page percentages match `comparison.json`.
